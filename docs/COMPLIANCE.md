# Telegram compliance and feasibility gate

**Status: UNRESOLVED / BLOCKING ALL REAL TELEGRAM DATA.** Review performed 2026-11-06. This document is engineering risk analysis, not legal advice or a permission grant.

## Official sources reviewed

- [Telegram API Terms of Service §1.5](https://core.telegram.org/api/terms): prohibits using, accessing or aggregating platform data to train, fine-tune or otherwise engage in the development, enhancement or **deployment** of AI/ML and similar technologies. §1.4 also forbids interfering with basic functionality, including actions without user knowledge/consent and preserving self-destructing content. §2.1 requires the application's own API ID; §2.2–2.4 address transparency and branding; §3.3 requires support for official sponsored channel messages where channels are accessible. These obligations must be assessed for the actual product.
- [Terms of Service for Content Licensing and AI Scraping](https://telegram.org/tos/content-licensing?setln=en): prohibits non-ordinary/unintended access; grants a limited, revocable, non-transferable, non-sublicensable license strictly to operate qualifying clients; also forbids scraping, indexing, harvesting, aggregating or using platform data for AI training, validation, development, enhancement, benchmarking or deployment. It states that exceptions **may** be granted when all relevant users individually provide explicit, informed, affirmative, continued consent specific to the content and context; one context's consent is not transferable. The text does not establish that a gateway owner's consent alone suffices or that an exception has been granted.
- [TDLib getting started](https://core.telegram.org/tdlib/getting-started) and [JSON client interface](https://core.telegram.org/tdlib/docs/td__json__client_8h.html): per-client instances, update-driven authorization, a non-concurrent receive loop, and asynchronous updates/responses. [setTdlibParameters](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1set_tdlib_parameters.html) accepts separate database/files directories and an encryption key. [getChatHistory](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1get_chat_history.html) has a maximum page size of 100, can return fewer and is not an unlimited export promise. [searchChatMessages](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1search_chat_messages.html) has search/database and secret-chat limitations. [updateMessageSendSucceeded](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1update_message_send_succeeded.html) and [resendMessages](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1resend_messages.html) show that send outcomes and retry eligibility are asynchronous and must not be guessed.

TDLib reference pages returned HTTP 403 to the page fetcher in this environment; the publicly indexed official documentation excerpts were reviewed via search. TDLib was built in a disposable development workspace and its ABI was tested with networking blocked and no parameters or credentials; no native adapter or live test exists. See `TDLIB_OFFLINE.md`. Refresh the sources and reassess before release.

## Intended data flows and risk

A personal Telegram account would synchronize chats, text and files into a per-account TDLib store; an authenticated AI client would request permitted records via gateway core and potentially transmit them to its model/provider, with writes going the other direction. Local indexing/search, caching, media retention, external model requests, and retaining or forwarding self-destructing/protected content may each implicate distinct contractual, consent, privacy and copyright obligations. Treating text as untrusted addresses prompt injection, not permission to use it.

**Confirmed from the text:** broad AI-related prohibitions; narrow client-operation license; consent described as context-specific and continuing; relevant API and other terms apply. **Unresolved legal interpretation:** whether this exact personal inference/use case is permitted at all, whether and how all relevant participants can provide and withdraw consent, whether provider transfer/sub-licensing, caching/indexing, public content and cross-account workflows are allowed, and how retention and deletion duties apply. Do not assume consent or the exception applies.

## Minimum release gate

1. Qualified counsel analyzes the intended flows and applicable terms, privacy, copyright and jurisdiction, or Telegram gives sufficiently specific written clarification/permission; record scope, conditions and evidence.
2. Owner explicitly approves the compliance decision and each real-account login/real-data use, credentials, deployment and external access, with a tested consent and withdrawal process if required.
3. Implement and independently review safeguards required by the decision, terms (including content protection/expiry and sponsored-message obligations where applicable), and product security requirements. Re-review current terms before enabling access.

Until then: synthetic fixtures only; no real accounts, authentication codes, Telegram synchronization, cache, export, forwarding, AI submission or live demos. An AI assistant cannot resolve this gate on the owner's behalf. Independent engineering and tests continue without crossing it.
