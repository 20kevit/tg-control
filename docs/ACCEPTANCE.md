# Acceptance and evidence matrix

This matrix distinguishes exercised **synthetic-only** capabilities from the requested live product. Test names refer to `tests/`. A green synthetic result is not evidence of real Telegram permission, a production security assessment, or live interoperability. See `STATUS.md` for dated commands and `ROADMAP.md` for remaining stages.

| Area | Present and exercised | Outstanding before the requested live gateway |
|---|---|---|
| Legal / privacy gate | Official terms researched, restrictions and owner decision documented (`COMPLIANCE.md`). Only synthetic fixtures and a network-blocked native ABI probe were used. | Qualified legal advice or written Telegram clarification/permission **and** explicit owner decision/approval. Do not log in, ingest or transmit real content until resolved. |
| TDLib / accounts | Isolated synthetic account state, lifecycle/errors and path-safe offline TDJSON correlation (`test_adapter.py`); native library built and two empty client IDs probed without parameters/network (`test_native_tdlib.py`, `TDLIB_OFFLINE.md`). | Clients and policy | Independent client tokens, rotation/revocation, account grants, separate Read/Write/Admin, exclusion precedence and explicit private-chat grants (`test_policy_auth.py`, `test_api.py`, `test_postgres_api.py`). | Production identity, token expiry/MFA, authentication throttling, operational abuse controls and independent security review. |

The following domains have authoritative contracts but must not be claimed implemented merely because the contract documents exist:

Evidence: `tests/test_events.py` (12 tests), `tests/test_events_jobs_api.py` (11 HTTP tests), migrations `0005`.
