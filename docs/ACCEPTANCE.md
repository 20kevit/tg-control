# Acceptance and evidence matrix

This matrix distinguishes exercised **synthetic-only** capabilities from the requested live product. Test names refer to `tests/`. A green synthetic result is not evidence of real Telegram permission, a production security assessment, or live interoperability. See `STATUS.md` for dated commands and `ROADMAP.md` for remaining stages.

| Area | Present and exercised | Outstanding before the requested live gateway |
|---|---|---|
| Legal / privacy gate | Official terms researched, restrictions and owner decision documented (`COMPLIANCE.md`). Only synthetic fixtures and a network-blocked native ABI probe were used. | Qualified legal advice or written Telegram clarification/permission **and** explicit owner decision/approval. Do not log in, ingest or transmit real content until resolved. |
| TDLib / accounts | Isolated synthetic account state, lifecycle/errors and path-safe offline TDJSON correlation (`test_adapter.py`); native library built and two empty client IDs probed without parameters/network (`test_native_tdlib.py`, `TDLIB_OFFLINE.md`). Unwired synthetic schema models conservatively classify visibility, screen text flags and distinguish acknowledgments/terminal send updates (`test_tdlib_read_model.py`, `test_tdlib_outcomes.py`). | No native TDLib adapter, actual account authorization, synchronization, multi-account session recovery, integrated protected/self-destructing-content handling or sponsored-message handling exists. |
| Clients and policy | Independent client tokens, rotation/revocation, account grants, separate Read/Write/Admin, exclusion precedence and explicit private-chat grants (`test_policy_auth.py`, `test_api.py`, `test_postgres_api.py`). | Production identity, token expiry/MFA, authentication throttling, operational abuse controls and independent security review. |
| Read / search / history / media | Synthetic discovery, metadata, history, chat and cross-account search, message and media retrieval through Core, filtered and reauthorized, including revocation races (`test_core.py`, `test_api.py`, `test_retention.py`). | Real TDLib pagination, sync completeness, unavailable/deleted/protected/ephemeral content, native media limits and Telegram search semantics are unimplemented. |
| Write / admin / batch | Synthetic send/edit/delete/forward/media and administrative actions; all targets preauthorized, per-item outcomes and non-atomic execution; replay keys and timeout/retry/reauthorization tested (`test_core.py`, `test_adapter.py`). | Real Telegram permissions and errors, asynchronous send confirmation, actual flood waits and safe unknown-outcome recovery need native integration and tests. |
| Interfaces | HTTP API, local CLI, MCP stdio and stateless Streamable HTTP, and owner Web Admin share Core/API. Health/schema routes also require credentials; official MCP SDK, subprocess and browser tests exercise auth, Host/Origin, policy, XSS and session handling (`test_mcp.py`, `test_stdio_process.py`, `test_cli.py`, `test_browser.py`). | Remote MCP uses static bearer tokens only; OAuth discovery/authorization and ChatGPT remote connector interoperability are not implemented or demonstrated. The static login bootstrap is not authenticated. Remote deployment requires owner approval, authenticated ingress for all paths and additional safeguards. |
| Audit / retention | PostgreSQL metadata/audit, no content/credential duplication in audit, owner-triggered pruning (90-day default), bounded reauthorized cache, optional encrypted synthetic state/media expiry and a cooperative single-instance guard (`test_api.py`, `test_retention.py`, `test_postgres_api.py`). | Automated audit pruning and durable alert delivery are absent; cleanup cannot run while offline, and filesystem snapshots/backups can retain older bytes. The instance guard is not distributed fencing; production observability, key rotation and retention validation remain. |
| Backup / recovery | Authenticated-encrypted PostgreSQL and optional synthetic-state backup; real local PostgreSQL restore and adversarial tests, including actual CLI subprocess (`test_backup.py`). | Requires offline writers, private plaintext scratch, separate keys and a newly created empty target. The catalog check is fail-closed but cannot prove absence of every exotic object or prevent concurrent changes. DB/files restore is not atomic. Disaster recovery under production conditions, restore automation and native TDLib state backup are untested. |
| Packaging / deployment | Hash-locked Python dependencies, wheel/assets/entry points and vulnerability checks; Docker/Compose configurations are syntactically and statically tested (`test_operational_config.py`). | Docker/Compose runtime unavailable here: image build/startup, image digest pinning, image/OS scans, deployment, backups under containers and production environment remain unverified. |
| Owner notification | While the gateway runs, a bounded background monitor records deduplicated synthetic session transitions and recovery in PostgreSQL/SQLite; the open panel displays recent events, current warnings and process-local monitor progress, and clears them on lock (`test_session_monitor.py`, `test_monitor_progress.py`, `test_postgres_api.py`, `test_browser.py`). | No push/email/SMS delivery, monitoring while the gateway is stopped, readiness/external-heartbeat signal, automatic stale threshold, or real TDLib session alerts; polling may miss brief transitions. |

The current full suite is documented in `STATUS.md`; the optional native ABI probe was also run successfully in an earlier 61-test version of the suite with networking blocked. Repeat the commands in `TESTING.md`; that optional probe is skipped without a trusted built library. Completion/release requires resolving every applicable outstanding item, not merely the synthetic rows.
